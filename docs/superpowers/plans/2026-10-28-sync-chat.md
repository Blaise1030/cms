# Sync as a Sidebar Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the modal, headless "combine" job with a sync chat in the agent sidebar that verifies itself after every turn and lands only when the draft is provably safe.

**Architecture:** A sync chat is a normal chat record with `kind = sync`, a cwd pointing at a durable merge worktree under `{state_dir}/sync/{chatId}/site`, and a `SyncState` block copied from the conflict session. The chat manager streams it like any chat; the turn-end hook routes `kind = sync` turns to a new `changes::sync_chat` module that verifies, builds, and lands. The old `AutoResolveJobs` machine, `SyncDialog`, questionnaire, and `result.json` contract are deleted.

**Tech Stack:** Rust (axum, tokio, serde), Vue 3 + Pinia + vitest, existing ACP chat manager, existing git plumbing (`conflicts`, `git`).

**Spec:** `docs/superpowers/specs/2026-10-28-sync-chat-design.md`

## Global Constraints

- User-facing copy is exactly the spec's table; vocabulary is only **project/site, change/draft, get latest, combine, publish, live**.
- Forbidden in any writer-visible string: `branch`, `commit`, `merge`, `conflict`, `worktree`, `checkout`, `clone`, `git`, `origin`, `main`, `markers`, `npm`, `<<<<<<<` (case-insensitive).
- Sync worktree: `{state_dir}/sync/{chatId}/site`; logs: `{state_dir}/sync-logs/{chatId}.log`.
- Build cap 300 s; per-turn watchdog 600 s (sync chats only); sync TTL 3600 s from `started_at`.
- Phases serialize snake_case: `working`, `checking`, `combined`, `ended`, `expired`.
- Event `sync.changed` payload: `{ projectId, conflictSessionId, chatId, phase }`.
- New chunk: `{"type":"sync_status","phase":"<phase>","text":"<copy>"}`.
- The draft branch moves only inside `sync_chat::land`, under `git::lock_for(project_dir)`.
- Only the human switches drafts; the sync agent never commits, aborts, or checks out.
- Chat ids are `random_token()[..16]`; ids must satisfy `transcript::valid_chat_id`.
- Rust tests: `cargo test`. Web tests: `pnpm -C web test -- <path>`.

## Review Focus

1. **A message sent while the sync is `checking`** must not race the build or land twice — expected: 409, chat stays read-only until verification finishes.
2. **The draft branch moves while the sync runs** (writer saves or publishes) — expected: `ended`, draft untouched, no land.
3. **The agent commits or aborts the merge** — expected: one plain note, phase `working`, no land.
4. **Daemon restart mid-sync, conflict session gone** — expected: resume from the record and still land, or end cleanly.
5. **Deleting the sync chat while a turn runs** — expected: turn stopped, worktree removed, no orphan, no transcript resurrection.
6. **A second sync for the same project** — expected: 409 and no second worktree.
