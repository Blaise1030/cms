# SEO Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an on-demand SEO audit of the running local preview, surfaced as a new SEO tab with per-finding "Open in preview" and "Fix with agent" actions.

**Architecture:** A new `src/seo/` daemon module crawls the project's dev server over loopback HTTP, parses HTML with `scraper`, and returns a typed report. One `POST /api/seo/audit` route exposes it. A `web/src/modules/seo/` Pinia store and panel render the report; fixes are sent through the existing chat outbox.

**Tech Stack:** Rust (axum, reqwest, tokio, scraper), Vue 3 + Pinia + Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-31-seo-audit-design.md`

## Global Constraints

- No browser dependency and no new service. The only new crate is `scraper = "0.29"`.
- Crawl only same-origin `127.0.0.1`, only paths under `/preview/{id}/`.
- Limits: 50 pages, 8 concurrent requests, 5 s per request, 30 s total, 2 MiB body prefix.
- Page paths in every payload are project-relative: `/` or `/pricing/` (trailing slash, no base prefix).
- `file` is repo-relative (`src/pages/index.astro`, `apps/web/src/pages/x.astro`) or `null`.
- Findings are plain language: no rule names, file paths, or git vocabulary in `message`.
- The panel is read-only. Fixes go through `useAgentOutboxStore().send({ kind: "text", text, submit: true })`.
- The starter template is not modified.
- Copy is fixed by the spec's table; do not improvise alternate wording.

## Review Focus

- A decorative `<img alt="">` must pass; only a missing `alt` attribute is a finding.
- `/x` and `/x/`, query strings, and fragments must collapse to one page and one set of findings.
- A 404 link must be reported on the page that links to it and must not appear in `pages`.
- A dev server that is starting or crashed must answer `DEVSERVER_ERR` with "Start the preview to run the audit", never hang.
- Every discovered link must be resolved against the `/preview/{id}/` base; a missed prefix makes all links look external or broken.

use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum Severity { Error, Warning }

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct Finding {
    pub rule: String,
    pub severity: Severity,
    pub page: String,
    pub message: String,
    pub detail: Option<String>,
    pub count: usize,
    pub file: Option<String>,
    pub fix: String,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct Summary { pub pages: usize, pub errors: usize, pub warnings: usize }

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct Report {
    pub project: String,
    pub duration_ms: u64,
    pub truncated: bool,
    pub timed_out: bool,
    pub summary: Summary,
    pub pages: Vec<Page>,
    pub findings: Vec<Finding>,
}

Create `src/seo/rules.rs` with `ParsedPage`, `Issue`, and the five functions. Use `scraper::{Html, Selector}`; selectors are constants parsed with `Selector::parse("…").expect("valid selector")`. Rules and messages, in output order:

| rule | condition | message |
| --- | --- | --- |
| `title-missing` | trimmed title empty | `This page has no title.` |
| `title-length` | `title.chars().count() > 60` | `The title is {n} characters; keep it under 60.` |
| `description-missing` | no non-blank description | `This page has no description.` |
| `description-length` | `description.chars().count() > 160` | `The description is {n} characters; keep it under 160.` |
| `heading` | `h1 == 0` | `This page has no main heading.` |
| `heading` | `h1 > 1` | `This page has {n} main headings; keep one.` |
| `image-alt` | any missing `alt` | `1 image has no alt text.` / `{n} images have no alt text.` |
| `html-lang` | no non-blank `lang` | `The page doesn't declare a language.` |
| `social-preview` | any of the three OG tags missing | `This page has no social preview tags.` detail lists the missing tags in `og:title`, `og:description`, `og:image` order, e.g. `Missing og:title, og:image.` |
| `noindex` | robots meta contains `noindex` (case-insensitive) | `Search engines are told not to index this page.` |
| `broken-link` | non-empty `broken` | `1 link is broken.` / `{n} links are broken.` detail = first five, `, ` joined |
| `duplicate-title` | title shared by >1 page | `Another page uses this title.` detail `Also used on /a/, /b/.` |
| `duplicate-description` | description shared by >1 page | `Another page uses this description.` detail as above |
| `robots-missing` | `!robots_ok` | `There's no robots.txt at the site root.` page `/` |
| `sitemap-missing` | `!sitemap_ok` | `There's no sitemap.xml at the site root.` page `/` |

`severity` is `Error` for `title-missing`, `heading` when zero, and `broken-link`; `Warning` for everything else, including `heading` when there is more than one. `count` is 1 except `image-alt` (number of images) and `broken-link` (number of targets). Cap `detail` at five entries and append no ellipsis.

- [ ] **Step 3: Implement normalization and the fetch loop**

Add `pub mod crawl;` to `src/seo/mod.rs`. Implement:

- `base_url`: `Url::parse(&format!("http://127.0.0.1:{port}/preview/{project}/"))`.
- `normalize`: join `href` against `base`; reject non-`http` schemes, a different origin, or a path outside `base.path()` (accept the base path with or without its trailing slash); strip the base prefix, collapse `//`, use `/` for empty, drop query/fragment, and normalize the display path to `/x/` (root stays `/`). Return `None` when `!is_crawlable`.
- `is_crawlable`: false for paths whose last segment has an asset extension (`css`, `js`, `mjs`, `map`, `json`, `xml`, `txt`, `png`, `jpg`, `jpeg`, `gif`, `webp`, `avif`, `svg`, `ico`, `woff`, `woff2`, `ttf`, `otf`, `pdf`, `zip`, `mp4`, `webm`) or that start with `/@`, `/node_modules/`, `/src/`, `/__orso`.
- `client`: `Client::builder().no_proxy().timeout(Duration::from_secs(5)).redirect(Policy::custom(move |attempt| { if attempt.url().host_str() == Some("127.0.0.1") && attempt.url().port() == Some(port) && attempt.previous().len() < 3 { Action::follow() } else { Action::stop() } })).build()` mapped to `ApiError::devserver("Start the preview to run the audit")`.
- `crawl`: breadth-first, starting with `["/"]`. Process levels with `futures_util::stream::iter(level).map(fetch).buffer_unordered(8)`. Fetch with a 5 s timeout, read at most 2 MiB, parse `text/html` with `rules::parse`, and push to `pages`. Record every fetched path in `statuses` (`0` on a transport error). Stop after 50 pages (`truncated`) or 30 s (`timed_out`). `root_status` is `statuses["/"]`, defaulting to `0`.
- Also fetch `robots.txt` and `sitemap.xml` once, after the page loop, and record them in `statuses` under those display paths.

Do not add per-request retries.

- [ ] **Step 3: Implement `audit` and the route**

In `src/seo/mod.rs`:

- `pub async fn audit(state: &AppState, project: &str) -> Result<Report, ApiError>`:
  1. `state.projects.get(project)` → `ENOENT` when missing.
  2. If `devserver != DevserverStatus::Ready`, return `ApiError::devserver("Start the preview to run the audit").with_status(409)`.
  3. Build `base_url(p.port, project)`, `client(p.port)`, and crawl. Measure `duration_ms`.
  4. If `root_status == 0`, return `ApiError::devserver("The preview didn't answer. Start it and try again.")`.
  5. Build `pages` from `crawl.pages` (`ParsedPage` → `Page`), sorted by path. If `root_status` is non-2xx, use one synthetic `Page { path: "/", status: root_status, title: "" }` and one `page-status` issue (`The home page returned HTTP {status}.`).
  6. Collect issues: each page's `page_issues`, `broken_link_issue` for resolved links whose `statuses` value is known and not 2xx, `duplicate_issues`, and `site_issues(robots_ok, sitemap_ok)`.
  7. Map `Issue` → `Finding` with `source_file` and `fix_prompt`; sort by page, severity (error before warning), then rule; build `Summary`.

```ts
import { defineStore } from "pinia";
import { ref } from "vue";
import { useDaemon } from "@/core/daemon";
import { errorMessage } from "@orso/utils";
import type { SeoReport } from "@/core/types";

export const useSeoStore = defineStore("seo", () => {
  const daemon = useDaemon();
  const reports = ref<Record<string, SeoReport>>({});
  const running = ref(false);
  const error = ref<string | null>(null);

  function reportFor(id: string): SeoReport | null { return reports.value[id] ?? null; }
  function clearError() { error.value = null; }

  async function run(id: string): Promise<void> {
    running.value = true;
    error.value = null;
    try {
      reports.value = { ...reports.value, [id]: await daemon.api.seoAudit(id) };
    } catch (e) {
      error.value = errorMessage(e);
    } finally {
      running.value = false;
    }
  }

  return { reports, running, error, reportFor, clearError, run };
});
```
